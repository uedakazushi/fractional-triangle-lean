# 仕様：何を計算し、何を証明するか

## 1. 数学的対象を列挙関数と独立に定義する

基礎体は C。一般化が役立つ箇所のみ代数閉・標数零の体 K で証明し、最後に C へ特殊化する。

```
n ≥ 3, a ≥ 1, p : Fin n → ℕ, ∀ i, 2 ≤ p i,
ν = 1 − Σ_i 1/(p i) > 0,
L = (ℤ^(n+1)) / ⟨p_i x_i − c⟩,
T = C[X_1,…,X_n] / (Σ_i X_i^(p_i)),
ω = c − Σ_i x_i,
τ ∈ L, a • τ = ω,
R = ⊕_{m∈ℕ} T_(m•τ).
```

R は実際の次数付き環として構成する。単に数値条件を満たすレコードを `RootRing` と改名して済ませない。L の torsion を消して ℤ に置き換えない。R の直和表現と T 内の部分環表現を必要に応じて同型で結ぶ。

対象は R のうち、n 変数多項式環を一つの非零斉次式で割った**最小表示**を持ち、その偏微分の共通零点が原点だけであるもの。形式的には、重みが全て正、f に定数項・一次項がなく、`∀ z, (∀ i, ∂ᵢf(z)=0) → z=0` と書ける。基礎体 C 上の全ての z を量化するので、数値的な有限検査ではない。Euler 恒等式で通常の孤立超曲面という解釈と結ぶ。

最小性・基礎体への忠実性・次数付き同型を仕様から落とさない。Gorenstein パラメーターは `h = a + Σ_i w_i` と同値な標準加群の次数差として対応を証明する。

## 2. 等価関係

分類は**次数付き C 代数同型**について行う。二つの方程式の行列の行列置換だけの同値、Hilbert 級数の一致、解析的同値、懸垂による安定同値のいずれでもない。

mathlib の既成の graded-isomorphism API が合わなければ、`AlgEquiv` に「各次数成分を保つ」を付加した自身の定義を作ってよい。この場合も環と次数成分は実際のものとし、条件を弱めない。

## 3. 計算側の入力・出力

純粋な関数 `enumerate` と CLI を分ける。提案するインターフェースは次のとおり（ここでの名前は新規設計名であり、mathlib の既存 API 名ではない）。

```
Input := { n : ℕ, a : ℕ, n_ge_three : 3 ≤ n, a_pos : 0 < a }
enumerate : Input → List EquationData
```

CLI は証明フィールドを受け取らず、整数入力から妥当性を判定する。`n<3`、`a<1`、負数・構文エラーは `invalid_input`。合法な入力で対象がない場合だけ成功した空リストを返す。OS のメモリ不足・打切り・未実装は失敗または `incomplete` であって、空リストの成功ではない。

`EquationData` は少なくとも以下を持つ。

- n と a、正の原始重み w、関係次数 h。
- 非零整数係数と指数ベクトルからなる正規化した有限支持多項式。初版の選ばれた可逆代表は全係数を +1 にできる。
- 元の signature p と、必要ならその順序、根 τ の繰り上がり正規形。
- 三変数では単項式写像 B と共通単項式の指数、出力変数と標準形変数の対応。
- 決定的な代表選択のキー。三変数では `(sort w, h)`、高次元では整列した p。

重みをソートしたら指数行列 E の**列**と B の**行**も同じ置換で移す。項の並べ替えは E の行の置換である。元の X の並べ替えは B の列と p に対応する。これらを混同すると JSON の式が表示重みに対して斉次でなくなる。

機械可読の大整数は十進文字列とし、`docs/OUTPUT_SCHEMA_ja.md` の規約を使う。出力の主たる数学データは有限支持多項式。見やすい文字列/LaTeX はその表示にすぎない。純粋な JSON encoder/decoder の round-trip を証明し、少なくとも機械可読の係数と指数を信頼対象にする。独立した TeX 文字列 parser の正しさまで初版の完成条件にはしない。

## 4. 必須の最終定理

以下を、列挙器の内部判定ではなく §1 の外在的な対象に対して証明する。

**健全性 `enumerate_sound`**：合法な入力の出力の各式は、対応する signature と実際の根 τ に対する R と次数付き同型であり、孤立・最小 n 生成・パラメーター a である。

**完全性 `enumerate_complete`**：任意の p、実際の τ、実際の R と、その孤立超曲面表示が与えられたとき、出力中に R と次数付き同型な式が存在する。n=3 を可逆式が既知の場合だけに限定しない。

**重複排除 `enumerate_pairwise_nonisomorphic`**：出力の異なる位置の式は次数付き同型でない。内部キーの `Nodup` だけではなく、キーによる同型判定を証明する。

**実装一致 `cli_payload_correct`**：CLI の正常出力を解析した構造は純粋な列挙関数の値である。少なくとも純粋 encoder の仕様を証明し、OS・端末・JSON 書込という未形式化の IO 境界を明記する。

**全域性**：合法な任意の有限 n,a について関数の停止が Lean に受理される。数学的全域性は有限メモリ機での実用的完走を保証しない。高速化は別関数と等価性定理で行う。

最終の宣言例の名前は `CanonicalRoots.enumerate_sound` 等に揃えられるが、引数型やシグネチャはまず契約として固定してから実装する。本文に未確認の Lean コードを貼ってコンパイル済みとはしない。

## 5. 隠れた仮定を禁止する

次は完成ではない。

```
variable (h_classification : ∀ R, Intended R ↔ Arithmetic R)
theorem full_classification ... := ... -- h_classification を引数に残す
```

`#print axioms` が標準三公理だけでも、この定理は分類定理を**仮定**している。同様に `ClassificationBridge`、`HasNormalForm`、`HasCoxLift` の未充足の型クラス引数を残さない。途中のモジュールの一般定理を補題として抽象化するのはよいが、公開最終定理で全て具体的な証明を与える。

対象述語を `e ∈ enumerate n a` と定義する、必要十分条件の片側だけを実装して iff とする、生成元数を最小でなくする、係数体を根拠なく Q のみに置き換える、といった仕様変更をしない。

## 6. 二種類の実行保証

A. 全入力について証明した純粋な列挙関数を通常の Lean executable として使う。この実行は通常のコンパイラー/runtime/OS を使う。

B. 特定入力の出力リストそのものを、`enumerate input = explicitList` の証明または**集合全体の完全性**を保証する verified checker の証明として保存し、カーネルで再検査する。

厳密な配布用一覧には B を併用する。各行だけを検査しても、漏れがないことの証明にはならない。外部 Python は候補と証明書の生成に使えるが、数学的 oracle として使わない。
